# Kufar watch bot

Telegram-бот, который сам проверяет категории наручных часов на kufar.by
(**все бренды**, не только Casio), находит новые объявления и присылает вам
карточку с оценкой (ценовая категория, риск, ожидаемая маржа, шанс успеха,
срок продажи, при наличии ИИ — оценка подлинности по фото) и кнопками
«✅ Одобрить» / «❌ Отклонить». Лоты с риском выше настраиваемого порога
вообще не присылаются. Одобренные лоты попадают в отдельный список, где
можно двигать статус (торгуюсь → куплено → выставлено → продано), а после
покупки — прислать свои фото и получить готовый текст объявления для
перепродажи (вставить на Kufar нужно вручную самостоятельно — сам бот туда
ничего не публикует, подробнее в разделе «Что бот не делает» ниже).

## Как это работает и что важно понимать заранее

- Бот НЕ ходит по страницам поиска Kufar (`kufar.by/l?query=...`) — они
  явно запрещены файлом `robots.txt` сайта для всех ботов. Вместо этого
  он читает обычные страницы категорий («Мужские наручные часы»,
  «Женские наручные часы») без параметров запроса — это разрешено.
- Бот присылает **все** объявления из этих категорий, кроме явного мусора
  (ремешки, запчасти, ремонт, батарейки — это не часы для перепродажи).
  Раз брендов теперь много, а не один Casio — предложений будет заметно
  больше, чем при узкой настройке. Список исключений и при желании
  сужение обратно до конкретных брендов — в начале файла `scraper.py`
  (переменные `JUNK_RE` и `BRAND_FILTER`).
- Ожидаемая цена продажи автоматически берётся в таком порядке: (1) если вы
  задали модель через `/addmodel` — используется она; (2) если для похожего
  «бренда» (грубо угаданного из названия) уже накопилось несколько цен —
  берётся их медиана; (3) иначе — медиана вообще по всем недавно виденным
  часам, очень грубо; (4) если данных совсем нет — поле останется пустым, и
  бот попросит вас вписать цену самостоятельно кнопкой «✏️ Указать цену».
  Чем больше моделей вы зададите вручную через `/addmodel`, тем точнее
  будут расчёты — с таким разбросом брендов (от безымянных до люксовых)
  это особенно важно.
- Это значит, что бот видит только первую страницу каждой категории (по
  умолчанию туда попадают самые свежие объявления) — этого достаточно,
  чтобы ловить новые лоты, но это не полный архив всех часов на сайте.
- Бот запускается не постоянно, а по расписанию — раз в 10 минут — через
  GitHub Actions. Это значит, что между «человек выставил объявление» и
  «бот вам его прислал» пройдёт до ~10 минут, а не мгновенно. Это
  осознанный компромисс ради полностью бесплатного и стабильного
  круглосуточного хостинга без серверов.
- Лоты с расчётным риском выше **30/100** автоматически не присылаются —
  порог задаётся константой `MAX_RISK_TO_SUGGEST` в `config.py`.
- Каждая карточка помечена ценовой категорией (бюджет / средний / выше
  среднего / премиум) — пороги в `config.py`, переменная `PRICE_CATEGORIES`.

## Что бот не делает (и почему)

Бот **не публикует объявления на Kufar сам** — это означало бы входить в
ваш личный аккаунт паролем, обходить капчу/смс-подтверждения и постить от
вашего имени ботом, а это прямо запрещено пользовательским соглашением
большинства маркетплейсов, включая Kufar, и рискует баном аккаунта. Вместо
этого бот готовит для вас готовый текст объявления (см. «📸 Собрать фото
для объявления» ниже) — вставить его на Kufar нужно вручную, это буквально
копирование текста и загрузка фото через обычную форму на сайте.

## Опционально: автопроверка подлинности и ИИ-описания (нужен свой API-ключ)

Если добавить секрет `ANTHROPIC_API_KEY` (см. шаг 4), появляются две вещи:

1. **Автопроверка подлинности по фото.** Сразу при обнаружении нового лота
   бот отправляет фото из объявления в Claude (Anthropic) и добавляет в
   карточку короткую оценку признаков оригинальности с вердиктом
   («похоже на оригинал» / «есть сомнения» / «похоже на подделку»). Это
   оценка по одной фотографии продавца, не экспертиза — финальное решение
   по личной встрече и осмотру вещи в руках остаётся за вами.
2. **Более живой текст объявления.** Когда после одобрения вы присылаете
   боту свои реальные фото уже купленной вещи и пишете `/done`, текст
   объявления пишет ИИ на основе этих фото и данных лота, а не шаблон.

Без ключа обе функции просто не работают: подлинность остаётся «не
проверено», а текст объявления собирается из простого бесплатного
шаблона — бот полностью работоспособен и без ключа.

Это платный API — у Anthropic, не у меня и не у GitHub. Стоимость одного
запроса с одним небольшим фото на модели Haiku — доли цента, но это
реальные деньги с вашей карты, привязанной к аккаунту console.anthropic.com.
Получить ключ: зарегистрируйтесь на [console.anthropic.com](https://console.anthropic.com),
пополните баланс на небольшую сумму и создайте API-ключ в разделе
**API Keys**. Актуальный список моделей и их точные идентификаторы —
на [docs.claude.com](https://docs.claude.com); если модель по умолчанию
(`claude-3-5-haiku-20241022`) устареет, задайте свою через переменную
репозитория `ANTHROPIC_MODEL` (Settings → Secrets and variables → Actions →
вкладка **Variables** → New repository variable).

## Шаг 1. Создать бота в Telegram и получить токен

1. Откройте в Telegram диалог с **@BotFather**.
2. Отправьте `/newbot`, придумайте имя и юзернейм (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AAExampleTokenHere`. Это ваш `BOT_TOKEN` — никому его не показывайте.

## Шаг 2. Узнать свой chat_id

1. Откройте диалог с **@userinfobot** (или любым похожим ботом, который показывает ваш ID).
2. Нажмите Start — он пришлёт ваш числовой ID, например `123456789`. Это `OWNER_CHAT_ID`.
3. Затем откройте диалог с вашим новым ботом (из шага 1) и нажмите **Start** — иначе бот не сможет писать вам первым.

## Шаг 3. Загрузить проект на GitHub

1. Зайдите на [github.com](https://github.com) и создайте аккаунт, если его ещё нет.
2. Нажмите **New repository**. Назовите как угодно (например `kufar-bot`), оставьте **Public**, ничего дополнительно не отмечайте, нажмите **Create repository**.
3. На странице пустого репозитория нажмите **uploading an existing file**.
4. Перетащите в окно браузера **всю папку** `kufar_bot` целиком (в Chrome/Edge это работает — перетаскивание папки подхватывает и вложенные файлы, включая скрытую папку `.github`). Если перетаскивание папки не сработает, перетащите файлы и папки по одной: сначала все `.py`-файлы и `requirements.txt` в корень, затем зайдите в `data/`, создайте там `state.json` таким же способом, и отдельно — `.github/workflows/bot.yml` (GitHub позволяет вписать путь `.github/workflows/bot.yml` прямо в поле имени файла при загрузке одного файла).
5. Нажмите **Commit changes**.

## Шаг 4. Добавить секреты

1. В репозитории откройте **Settings → Secrets and variables → Actions**.
2. Нажмите **New repository secret**, имя `BOT_TOKEN`, значение — токен из шага 1. Сохраните.
3. Ещё раз **New repository secret**, имя `OWNER_CHAT_ID`, значение — ваш ID из шага 2. Сохраните.
4. (Необязательно) Если хотите автопроверку подлинности по фото и более
   живые описания объявлений — добавьте ещё один секрет с именем
   `ANTHROPIC_API_KEY` (см. раздел «Опционально: автопроверка подлинности
   и ИИ-описания» выше про получение ключа и связанные расходы). Без этого
   секрета бот прекрасно работает и так, просто без этих двух функций.

## Шаг 5. Включить и проверить

1. Откройте вкладку **Actions** в репозитории. Если GitHub спросит разрешения — нажмите **I understand my workflows, go ahead and enable them**.
2. Слева выберите workflow **Kufar Casio watch bot**, справа нажмите **Run workflow** → **Run workflow** — это запустит бота прямо сейчас, не дожидаясь расписания.
3. Через минуту-две откройте чат с ботом в Telegram и напишите `/start` — должно прийти приветственное сообщение со списком команд.
4. Если в ближайшее время на Kufar появится новое объявление с Casio/G-Shock — бот пришлёт карточку с предложением при следующем запуске (раз в 10 минут).

Дальше ничего делать не нужно — расписание в `.github/workflows/bot.yml` запускает бота автоматически каждые 10 минут, 24 часа в сутки, полностью бесплатно.

## Команды бота

- `/queue` — заново показать текущие предложения на одобрение (отсортированы по цене).
- `/approved` — список одобренных лотов в работе со статусами (тоже по цене).
- `/stats` — в обороте / реализованная прибыль / продано лотов / доля прибыльных сделок.
- `/models` — список моделей, для которых вы задали ориентир цены продажи.
- `/addmodel ключ цена [high|medium|low]` — задать ориентир цены продажи и ликвидность для модели, например: `/addmodel ga-2100 250 high`. Ключ ищется как подстрока в названии объявления (регистр не важен).
- `/delmodel ключ` — удалить модель.
- `/done` — закончить присылать фото для объявления и получить готовый текст (см. ниже).

Под каждой карточкой лота есть кнопки: одобрить/отклонить, указать ожидаемую цену продажи (бот попросит прислать число следующим сообщением), а для одобренных — сменить статус, отметить проданным (тоже с запросом фактической цены) или **«📸 Собрать фото для объявления»**.

### Как получить готовый текст объявления

1. Одобрите лот, а когда физически купите часы — нажмите под карточкой **«📸 Собрать фото для объявления»**.
2. Пришлите боту одно или несколько своих реальных фото уже купленной вещи (по одному сообщению на фото).
3. Напишите `/done` — бот пришлёт готовый текст (заголовок + описание), который останется скопировать и вставить в форму создания объявления на Kufar самостоятельно, вместе с фото.

Без `ANTHROPIC_API_KEY` текст будет простым шаблоном по данным лота (без учёта того, что на фото) — тоже рабочий вариант, просто менее «живой».

## Как расширить

- **Больше категорий**: список `CATEGORY_URLS` в начале файла `scraper.py` (сейчас мужские и женские наручные часы).
- **Сузить обратно до конкретных брендов**: впишите регулярки в `BRAND_FILTER` там же — тогда будут проходить только совпадения, как было с Casio изначально.
- **Отсеивать ещё что-то как мусор**: дополните `JUNK_RE` в `scraper.py`.
- **Частота проверки**: строка `cron: "*/10 * * * *"` в `.github/workflows/bot.yml` (GitHub не гарантирует более частый запуск, чем раз в 5 минут).
- **Сколько новых объявлений разбирать за раз**: константа `MAX_NEW_ITEMS_PER_RUN` в `config.py` (по умолчанию 30) — увеличьте, если в первый запуск объявлений находится больше, чем бот успевает разобрать.
- **Порог риска для показа лота**: константа `MAX_RISK_TO_SUGGEST` в `config.py` (по умолчанию 30) — можно также переопределить переменной репозитория `MAX_RISK_TO_SUGGEST` (Settings → Secrets and variables → Actions → Variables), без правки кода.
- **Ценовые категории**: список `PRICE_CATEGORIES` в `config.py`.

## Если что-то не работает

Откройте вкладку **Actions** → последний запуск workflow → посмотрите лог шага **Run bot**. Там печатаются предупреждения (`[warn] ...`), если, например, не удалось получить обновления от Telegram или разобрать страницу Kufar. Разметка сайта Kufar может со временем немного меняться — если бот перестанет находить объявления, в первую очередь стоит проверить актуальность регулярных выражений в `scraper.py` (можно прислать мне свежий пример объявления, и я обновлю парсер).
